This release adds two analyzers that look at how a server is exposed, makes the triage of findings stricter about what it can prove, and records more about a server in its inventory.

New analyzers. `transport` reports MCP endpoints that other machines or web pages can call without credentials: a server that listens on every interface, CORS open to any origin, an endpoint with no authentication. Each is weighed against what the server's tools reach. Rules: `transport.network_exposed`, `transport.browser_reachable`. `iac` reports database and admin passwords that shipped Bicep, ARM JSON and Terraform templates fix or make predictable. Rules: `iac.hardcoded_secret`, `iac.predictable_secret`.

The scanner's own edges. Files of a scanned tree are read through its root, regular files only and up to the size that was parsed; a link out of the tree, a special file or an oversized one is refused, a refused read is reported as a limit, and it never lowers a finding. Target arguments, headers and URLs are redacted in reports more widely, including the value of a `--header` argument, keys in a URL path, tokens with a known prefix and JWTs. On Unix a stdio target runs in a process group of its own and what is left of it ends with the session. The scan API refuses a `Host` outside its allowed hosts, a foreign `Origin`, and a POST body that is not JSON; `MCP_SCANNER_API_ALLOWED_HOSTS` and `MCP_SCANNER_API_ALLOWED_ORIGINS` configure it. Oversized esbuild bundles are read by their own modules, package scans carry the version the registry served (`target.resolved_version`) and query OSV at that version, and a resource's URI and description are read from where they are written.

Triage. What a check, a test folder, a description or a name proves is read more carefully. A regular-expression check before a sink closes the path only when it stands on it. A finding whose path lies in test or evaluation code is context only when the tree says the file is not run. A tree where nothing says MCP reports its paths as context. Content read from a location the code fixes itself, a call-order hint to a tool of the same server, and a SQL method matched by name on another service's client with no SQL text are context. Library calls count as a check only when their verb ends at a word and the call does not act (`checkpoint`, `ensureDir` and `verifyToken` do not). A credential goes by where it ends: one sent to an address the caller chooses, or put in the tool's result, is a leak at `CRITICAL`, one that goes only to the server's own fixed or configured host is `MEDIUM` for review. Caller text in an `osascript -e` script is command injection, for review. A network call is reported for a scope word in a description only when it carries the caller's data; otherwise it is context.

Verdict. A completed scan with nothing worse than `LOW` is no longer `UNSAFE`: the default blocking severity is `MEDIUM`. Set `blocking_severity: low` in the config file to keep the former behavior. `--fail-on` is unchanged.

Inventory. Each capability can carry `behavior.egress` (hosts its code names, addresses its settings give, calls whose address the caller's data starts, calls that carry a credential), `effects` (files it writes, programs it runs, data it sends, text it reads from outside), `annotations` and `annotation_conflicts` (the hints its registration spells, and where the code it reaches disagrees), and `not_traced` (a backend of its own it hands work to, which the scanner does not follow). A server carries the `transports` its code starts, and the inventory the `combination` of what its capabilities do together. They are names along the calls, not a traced flow; no analyzer reads them, and findings do not depend on them.

Analysis is faster on trees with many calls: the call graph indexes calls by their caller.

Expect different results than on v1.2.0. Some findings that were potential or for review are now context, and some new ones appear, most of them from the `transport` analyzer. Read `triage` before acting on a finding: `potential` is static evidence of a flow, not proof that it can be exploited. Static analysis still misses tools registered in forms the scanner does not know, values that pass through code it cannot follow, and behavior of libraries. A `SAFE` verdict says that nothing the scan covers blocks, not that the server has no issue.
