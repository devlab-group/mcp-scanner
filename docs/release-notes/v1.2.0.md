This release changes how far a finding can be relied on, and says so in the report. Every dataflow finding now carries `triage` (`confirmed`, `potential`, `needs_review` or `context`) with a `triage_reason`, plus where its path starts (`source_class`) and whether an MCP handler reaches it (`reachability`, `reachable_from`). A tool whose stated purpose is the risky action, such as a tool that runs shell commands, is reported as a declared capability (`finding_kind: dangerous_capability`) instead of an injection into it. Anything the scanner decides from names or wording alone goes to `needs_review`; only facts of the code remove a finding.

A new `inventory` command writes a dossier of a source tree: manifests and their MCP SDK versions, server identity, and for each tool, prompt and resource its handler, parameters and observed behavior, with review hints for what static analysis could not decide (see `docs/review-hints.md`).

Tool discovery covers more registration forms: the Python SDK 2.x `Server(on_call_tool=...)` and `Server[T]`, mcp-go `ServerTool` literals, the Java SDK's `SyncToolSpecification`, Spring AI `@McpTool`, decorator calls such as `mcp.tool()(fn)`, tools lists in imported constants, and hand-written JSON-RPC servers. A tree with several low-level servers now sends each server's tools to its own dispatcher; before, one dispatcher was picked for the whole tree, and which one could change between runs.

Dataflow analysis follows more of a project's own code: what a function returns after it checks or rebuilds a value, checks two calls below a handler, argv lists built elsewhere, schemas defined in another file, and commands stored by one tool and run later. Many false-positive classes are gone, among them SQLAlchemy statements, `?` placeholders, typed `int`, `bool`, enum and `Literal` parameters, fixed-host URLs, `exec.LookPath`, built-in `Map` and `dict` methods that share a name with a project method, and path checks counted as a guard for a shell command line. Supply chain checks read `uv.lock`, keep development-only packages in context, and retry OSV on transport errors.

Analysis budgets no longer depend on machine load: the per-file parse budget counts thread CPU time and the taint walk has a fixed work limit. The per-analyzer timeout is 5 minutes by default and is the one limit left that a busy machine can hit; when it does, the report says so in `limits_hit`.

Expect different results than on v1.1.1. Many findings that were plain HIGH are now `needs_review` or a declared capability, and fewer are reported overall. Trees that used to show no tools may now show many, with new findings in their handlers. Read `triage` before acting on a finding: `potential` is static evidence of a flow, not proof that it can be exploited.
